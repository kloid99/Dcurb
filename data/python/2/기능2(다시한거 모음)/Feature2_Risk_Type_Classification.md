# Feature 2. 행정동 위험유형 자동 분류

## 1. 기능 목적

행정동별 DLFI 점수뿐 아니라 해당 지역이 왜 위험한지를 설명하고, 주요 위험원인과 기본 정책 검토 방향을 함께 제공한다.

기능 2는 다음 질문에 답한다.

- 이 행정동의 DLFI가 높은 주요 원인은 무엇인가?
- 한 가지 위험이 우세한가, 여러 위험이 동시에 높은가?
- 어떤 정책을 먼저 검토해야 하는가?
- 기존 K-Means 군집 결과와 규칙 기반 결과가 어떤 관계인가?

## 2. 입력 데이터

기본 입력 파일은 `final_modelling.csv`이며, 행정동 82개와 다음 6개 DLFI 세부 지표를 사용한다.

| 위험요인 | 입력 컬럼 | 위험방향 |
| --- | --- | --- |
| 배송수요 | `배송수요점수_최종` | 높을수록 위험 |
| 하역공간 부족 | `하역여유점수` | 낮을수록 위험 |
| 단속반복 | `단속반복점수` | 높을수록 위험 |
| 보행충돌 | `보행충돌점수_최종` | 높을수록 위험 |
| 교통방해 | `교통방해점수` | 높을수록 위험 |
| 안전취약 | `안전취약점수` | 높을수록 위험 |

`하역여유점수`는 다른 지표와 위험방향이 반대이므로 값이 낮을수록 높은 위험점수가 되도록 변환한다.

조원 통합 파일은 다음과 같이 구분해 사용한다.

| 파일 | 확인 결과 | 기능 2 사용 방식 |
| --- | --- | --- |
| `final_modelling.csv` | 82행·38컬럼 | 위험유형 분류의 공식 입력 |
| `logistics_view_timeband_v3.csv` | 492행·82동×6시간대 | 물류기업 화면의 혼잡도·배송집중도 |
| `driver_view_timeband_v3.csv` | 492행·82동×6시간대 | 배송기사 시간대 등급·실측검증 |
| `driver_facing_policy_text.csv` | 11개 정책문구 | 원본 정책을 기사 안내문구로 변환 |
| `DLFI_탄력주정차_82동_대시보드용_v2.csv` | 82행 | 기능 1 화면 연결 |
| `탄력주정차_행정동매핑_DLFI조인_v2.csv` | 55구간·15개 동 | 기존 탄력주정차 구간 연결 |

시간대 파일과 탄력주정차 파일은 화면 연결에만 사용하며 위험유형을 다시 계산하는 입력으로 사용하지 않는다.

## 3. 위험유형 체계

| 위험유형 | 판정 의미 | 기본 정책 방향 |
| --- | --- | --- |
| 배송수요 과밀형 | 배송수요 위험점수가 가장 높음 | 배송시간 분산·공동배송 검토 |
| 하역공간 부족형 | 하역공간 부족 위험점수가 가장 높음 | 임시 하역면·공영주차장 유휴면 검토 |
| 단속반복형 | 단속반복 위험점수가 가장 높음 | 탄력 하역권·허용시간·안내표지 검토 |
| 보행충돌형 | 보행충돌 위험점수가 가장 높음 | 보행 피크시간 회피·완충구간 검토 |
| 교통방해형 | 교통방해 위험점수가 가장 높음 | 혼잡시간대 하역 회피·차로 점유 최소화 |
| 안전취약형 | 안전취약 위험점수가 가장 높음 | 등하교·취약계층 이동시간 회피 |
| 복합위험형 | 상위 3개 위험점수가 모두 70점 이상 | 상위 3개 유형의 정책을 결합 검토 |

## 4. 분류 절차

### 4.1 위험방향 표준화

6개 지표는 분포와 척도가 다르므로 82개 행정동 안에서 위험방향 백분위로 변환한다.

- 높은 값이 위험한 지표: 원점수가 높을수록 높은 백분위 부여
- 낮은 값이 위험한 하역여유: 원점수가 낮을수록 높은 백분위 부여
- 출력 범위: 0~100점

표준화 점수는 원점수를 변경한 절대위험 확률이 아니라 행정동 간 상대적 위험 위치를 뜻한다.

### 4.2 주요 위험요인 TOP 3 추출

행정동마다 표준화 위험점수 6개를 내림차순으로 정렬해 주요 위험요인 1~3순위를 추출한다.

### 4.3 복합위험 판정

TOP 3 점수가 모두 70점 이상이면 `복합위험형`으로 판정한다.

복합위험형의 화면 표시명은 상위 2개 위험요인을 결합한다.

예:

```text
보행충돌·단속반복 복합위험형
배송수요·하역부족 복합위험형
```

### 4.4 기본유형 판정

복합위험 조건을 충족하지 않으면 가장 높은 위험요인의 기본 유형을 부여한다.

- TOP 1이 75점 이상: 강한 기본유형
- TOP 1이 75점 미만: 관찰 기본유형

모든 행정동은 6개 기본 유형 또는 복합위험형 중 하나로 분류된다.

### 4.5 지역 특성 결합

공동주택·상권·역세권 명칭은 다음 실제 보조지표가 연결되고 70점 이상일 때만 접두어로 사용한다.

| 지역특성 | 허용 근거 |
| --- | --- |
| 공동주택 | 공동주택 세대 비중 또는 공동주택 비중 |
| 상권 | 상가 수 또는 상권 밀도 백분위 |
| 역세권 | 대중교통·도시철도 승하차 백분위 |

현재 `final_modelling.csv`에는 위 세부 근거 컬럼이 없으므로 결과 파일에서 지역특성 태그는 `미산출`로 표시한다. 기존 K-Means의 군집명을 지역특성 근거로 대신 사용하지 않는다.

## 5. K-Means 활용 원칙

K-Means는 최종 위험유형을 결정하지 않는다.

| 구분 | 역할 |
| --- | --- |
| 규칙 기반 분류 | 대시보드 대표 `위험유형` 결정 |
| K-Means | 행정동 패턴·군집 일관성 보조 확인 |

기존 `군집`과 `위험유형`은 결과 파일에서 `기존KMeans군집_보조`, `기존KMeans유형_보조`로 이름을 바꿔 보존한다. 사용자 화면에는 규칙 기반 `위험유형` 하나만 대표값으로 노출한다.

## 7. 출력 파일

### 7.1 `risk_type_master.csv`

주요 출력 컬럼은 다음과 같다.

| 컬럼 | 설명 |
| --- | --- |
| `위험유형` | 대시보드에 표시하는 단일 대표 유형 |
| `기본위험유형` | 6개 기본 유형 또는 복합위험형 분류군 |
| `복합위험여부` | TOP 3 모두 70점 이상인지 여부 |
| `복합판정근거` | TOP 3 최저점과 임계값 비교 |
| `지역특성태그` | 실제 보조데이터가 있을 때만 산출 |
| `주요위험요인1~3` | 표준화 점수 기준 TOP 3 |
| `주요위험점수1~3` | TOP 3의 0~100점 |
| `한줄자동해석` | 행정동·유형·원인을 결합한 설명 |
| `권장정책` | 유형별 규칙 기반 기본 검토안 |
| `기존KMeans군집_보조` | 기존 군집 결과 |
| `기존KMeans유형_보조` | 기존 군집 유형명 |
| `SHAP_TOP1~3_변수_보조` | 원본 RandomForest 설명 근거 |
| `모델추천정책_원본` | 조원 통합본의 기존 정책 결과 |

### 7.2 `risk_type_rules.csv`

복합위험형과 6개 기본 유형의 판정조건, 기준점수, 대표지표, 정책 연결, K-Means 역할을 기록한다.

## 8. Streamlit 화면

Streamlit 화면은 무채색 UI로 구성하며 다음 기능을 포함한다.

- 행정동 선택
- 위험유형 필터
- DLFI·위험유형 상세 카드
- 6개 지표 레이더 차트
- 주요 위험원인 TOP 3
- 유사 유형 지역
- GeoJSON 기반 DLFI 위험지도
- 유형별 정책 추천
- 두 지역 위험도 비교
- 분류 근거와 K-Means 보조 결과
- 지자체·물류기업·배송기사 화면
- 물류기업 6개 시간대 혼잡도·배송집중도
- 배송기사 추천·보통·회피 등급과 실측검증 플래그
- 기사 안내문구 자동 연결
- 팀 기능 1·3·4 연결 구조

기능 2 화면에서는 임의의 정책 효과 What-if 계산을 수행하지 않는다. 기능 2의 위험유형과 추천 정책을 기능 3에 전달하고, 실제 정책 효과 계산은 기능 3에서 담당한다.

## 9. 한계와 해석 주의사항

- 표준화 위험점수는 행정동 간 상대적 백분위이며 사고확률이나 예측확률이 아니다.
- 복합위험 임계값 70점은 MVP 규칙이며 운영 단계에서 정책 담당자 검토와 현장 검증을 거쳐 조정해야 한다.
- 지역특성 접두어는 실제 근거 컬럼이 연결되지 않으면 표시하지 않는다.
- K-Means 군집과 최종 위험유형이 다를 수 있으며, 두 결과는 목적이 서로 다르다.
- 추천 정책은 우선 검토안이며 정책 효과를 확정적으로 보장하지 않는다.
